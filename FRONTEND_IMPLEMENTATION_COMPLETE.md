## Integration Points to Verify

### Backend Endpoints Used
```
POST /api/payments/create-payment
- Called on payment screen load with paymentMethod="stripe" (default)
- Called again when switching payment methods
- Returns payment response with amount, clientSecret (Stripe), or receiver_number (Easypaisa)

POST /api/payments/submit-proof (Easypaisa only)
- Called when user submits proof
- Updates payment status to "pending_review"

GET /api/payments/admin/pending-easypaisa (Admin only)
- Called when admin opens Payments screen
- Returns list of pending Easypaisa payments

POST /api/payments/admin/confirm-payment (Admin only)
- Called when admin clicks "Confirm Payment"
- Updates payment status to "paid"
- Creates appointment with status="confirmed"
```

## API Response Examples

### Create Payment (Stripe)
```json
{
  "payment_method": "stripe",
  "clientSecret": "pi_1234567890_secret_abc123",
  "paymentId": "pay_1234567890",
  "amount": 5000,
  "currency": "usd",
  "message": "Stripe PaymentIntent created"
}
```

### Create Payment (Easypaisa)
```json
{
  "payment_method": "easypaisa",
  "receiver_number": "03144828190",
  "amount": 5000,
  "currency": "usd",
  "paymentId": "pay_1234567890",
  "status": "pending",
  "instructions": "Send PKR 13,900 to Easypaisa number..."
}
```

### Submit Proof Response
```json
{
  "message": "Payment proof submitted successfully. Admin will review shortly.",
  "payment_id": "pay_1234567890",
  "status": "pending_review"
}
```

### Admin Confirm Payment Response
```json
{
  "message": "Payment confirmed successfully. Booking is now active.",
  "payment_id": "pay_1234567890",
  "appointment_id": "appt_1234567890",
  "status": "paid"
}
```
